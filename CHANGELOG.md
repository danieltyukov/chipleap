# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Chips are timed at their ports, through their pads: after routing, OpenSTA times the whole chip at every corner LibreLane signed it off at, with IHP's `sg13g2_io` liberty of the same process, core supply and temperature, which has the pads' arcs, clocks created on their pads' ports and the data ports constrained by `chip.io` (input and output delay, output load, input edge rate; the delays default to a fifth of the period). The chip report gives each corner's worst slack at the ports and the worst pad-to-core, core-to-pad and pad-to-pad paths at the slow corner, with the delay inside the pads; a pad whose IO cell has no arc is reported as not timed and fails the chip, and a budget outside the range IHP characterised the pads for is a warning. The UART chip's slow-corner setup slack is +0.971 ns at its ports, against +6.302 ns at the core's side of the pads.
- macro/v1 rule `pdk.cell_name` (error): for a package built for `ihp-sg13g2`, the package's name, its GDS cells and its subcircuits, with ASCII case folded, may not begin with `sg13g2` or `rm_ihpsg13`, the name spaces of the PDK's own cells, since a chip merges layouts and netlists by cell name. Given the PDK's libraries (`chipleap macro check --pdk-libs DIR`), a name equal to one of their cells is refused too. The spec and the shared fixtures carry the rule, with a new broken fixture, `pdk-cell-name`.
- macro/v1 rule `pdk.cell_name` lets a package hold the PDK's own standard cells: a hardened digital block's GDS holds the standard cells it uses under their own names, which the rule refused. With the PDK's libraries (`--pdk-libs`, `check_package(pdk_libs=...)`), a GDS cell named exactly like a cell of the standard-cell GDS a chip merges (LibreLane's `CELL_GDS`, `libs.ref/sg13g2_stdcell/gds/sg13g2_stdcell.gds`) passes when the two are identical and every cell it places is the PDK's own too. Identical means the same database units (one UNITS record in each file, before its first structure, the same bytes) and the same records from BGNSTR to ENDSTR, BGNSTR's dates left out, so STRCLASS, properties and the order of elements count (`chipleap.macro.gds.structure_identities`, which `chipleap.chip.merge` now uses too). A cell of another library, a name the standard-cell GDS defines twice, a name in another case and the package's top cell never pass this way, and without the libraries every GDS cell in the name space is still refused, since it cannot be shown to be the PDK's own. The package's name and the SPICE file's subcircuits stay errors: a netlist instantiates the PDK's cells and LVS takes them from the PDK's CDL. A LibreLane-hardened block's standard cells are the PDK's own this way. The spec and the shared fixtures carry the change, with stand-in PDK libraries (`pdk/`) and new cases `std-cell-identical`, `std-cell-modified`, `std-cell-child`, `std-cell-units`, `std-cell-strclass`, `std-cell-twice`, `std-cell-other-library` and `spice-pdk-subckt`.
- A chip places a LibreLane-hardened block that holds the PDK's standard cells: the chip step checks every package with the PDK's libraries (`chipleap.chip.assemble.import_macros`, which stops the step when it cannot read them), and the import accepts the standard cells `pdk.cell_name` shows to be the PDK's own, in any number of packages; every other cell of a package must still carry its name. After LibreLane runs, `chipleap.chip.merge` compares those cells again, the same way, with the standard-cell GDS it merged.
- `chipleap doctor` runs a self-test of the SymbiYosys and EQY ChipLeap would use: a reachable cover, an `abc pdr` proof and, with EQY, two equal designs, each with a known answer. A build that does not match the Yosys it drives (and answers wrong without failing) fails `doctor` with the binary and the variable to set. The formal step reports an error, not a pass or a fail, when SymbiYosys's summary contradicts its engine about a cover or an assertion.
- Bring your own RTL: every step after architecture runs on Verilog or SystemVerilog you wrote. A project file, `project.yaml`, names the top, sources or a filelist, include directories, defines, parameters, clocks, resets, technology, cocotb tests and an optional Python golden model; `chipleap project init` writes one for existing RTL, guessing the top, clock and reset, and `chipleap project check` shows it with every default filled in. [docs/projects.md](docs/projects.md) describes it.
- `chipleap verify PROJECT` runs lint (Verilator `-Wall`, and slang `-Wextra` when installed), the cocotb tests (Icarus or Verilator 5.036 or newer), coverage (Verilator line, branch and toggle, per file, with the points never reached), synthesis (Yosys on the technology's cells: area, flip-flops, critical path, an Fmax estimate and the mapped netlist) and, with `--steps all`, place and route with LibreLane on IHP SG13G2 with the accelerator's slow-corner signoff and constraints written from the project's clocks. Results go to `build/verify/report.html`, `VERIFY.md` and `verify.json`. A failing test is reported by name with the file and line where it failed.
- Commercial tools for projects: the cocotb tests on Xcelium, VCS or Questa, synthesis with Genus or Design Compiler, place and route with Genus and Innovus, here or on a server with `--remote`.
- MCP tools for projects: `describe_project`, `lint_rtl`, `simulate_rtl`, `coverage_rtl`, `synthesize_rtl` and `verify_rtl`, with structured diagnostics (tool, severity, file, line, column, code, failing test) so an assistant can fix RTL in a loop; a `fix_rtl` prompt and a `chipleap://project-reference` resource. `chipleap replay` re-runs the project tools, and when a result differs it says whether the project's files or the tools changed since the call.
- `examples/uart`: a UART with cocotb tests and a reference model. It routes on IHP SG13G2 at 100 MHz with clean DRC, LVS and antenna checks: 325 cells on a 0.0084 mm2 core, 5.7 ns of setup slack at the slow corner (about 234 MHz there, 308 MHz at the typical corner).
- `chipleap doctor` lists Icarus, slang and whether Landlock confines tools; `pip install "chipleap[rtl]"` adds cocotb.
- Design for test for RTL projects: with a `dft` section, OpenROAD replaces the flip-flops with scan flip-flops and stitches the chains, ChipLeap traces every chain through the netlist, Fault with Quaigh generates stuck-at patterns and reports their coverage, the patterns go to `patterns.json` and a STIL file, and a flush pattern and the first patterns are simulated through the chains of the scan netlist and, once routed, of the routed netlist on Icarus 13. Place and route then routes the scan netlist. The UART gets three chains of 17 flip-flops, 99.2 % coverage with 39 patterns, and routes clean.
- Gate-level power: the `power` step runs the project's cocotb tests on the routed (or synthesized) netlist with IHP's cell models, dumps a VCD, and reports OpenROAD's power from that activity next to the vectorless figure, per group, at the typical, slow and fast corners. Tests on a netlist see `GATES=yes` and the project's parameters as JSON in `CHIPLEAP_PARAMETERS`.
- IR drop: the `ir_drop` step runs OpenROAD's PDNSim on the routed power grid with the tests' activity and reports the worst and average drop per supply net, the worst cells and a map.
- Power intent: a `upf` section lists power domains; OpenROAD reads the UPF ChipLeap writes, places each domain's cells in its own region, and the step lists the signals between domains, failing when domains of different voltages meet without the level shifters IHP's library lacks. No open simulator is power aware, and the documentation says so.
- Engineering change orders: `chipleap eco PROJECT` and the `eco` step resize gates, insert buffers or repair timing on the routed design and sign it off again (routing, timing at every corner, DRC, LVS, antenna) from the state before detailed routing, without placing it again; `--paths` lists the worst paths stage by stage. On the UART a resized gate re-routes and signs off clean in about a minute and a half; on a multiplier that misses setup at the slow corner by 0.3 ns, `repair: setup` closes it.
- MCP tools `dft_rtl`, `power_rtl`, `ir_drop_rtl`, `upf_rtl`, `timing_paths_rtl` and `eco_rtl`, and a `fix_timing` prompt. `chipleap replay` re-runs `dft_rtl` and `upf_rtl`.
- `chipleap doctor` lists OpenROAD, a gate-level Icarus (13 or newer, `CHIPLEAP_GL_IVERILOG`), Fault and Quaigh.
- A project's files stay inside its directory: every path must resolve there, symlinks followed, unless you allow another directory with `--allow-path` or `CHIPLEAP_ALLOW_PATHS`, and values that a Yosys or Tcl script would read as syntax are refused, then quoted again when scripts are written. Every `` `include `` and `$readmem` file the RTL names by a string must be inside too, and on Linux with Landlock the lint and synthesis tools can read only the project, the system and their own files, so an `` `include `` a macro builds cannot bring another file into a diagnostic (`CHIPLEAP_CONFINE=0` turns that off). Verifying a project runs its cocotb tests and golden model, which are code: verify only projects you trust. A tool that fails in an unexpected way (a timeout, a missing program, a truncated results file) fails its step; the other steps and the reports still run.
- Macro packages (`macro/v1`), the format ChipLeap and aispice use to hand hardened blocks to each other: `macro.toml` plus GDS, LEF, liberty, Verilog model, SPICE netlist, a measured spec table for analog blocks and DRC and LVS evidence. `chipleap macro check DIR [--pdk NAME[@COMMIT]]` checks a package with the same rules, rule ids and messages as `aispice macro check`: the manifest against its JSON schema (`chipleap macro schema`), the files each kind needs, every pin across the GDS, LEF, liberty, Verilog and SPICE views, the size, timing arcs of digital outputs, measured specs against their limits, and evidence that passes, matches the package files and names the same PDK. Evidence follows OpenADA's result envelope, and OpenADA results are accepted as they are. The MCP server has a `check_macro` tool, and `chipleap.macro` reads and writes packages for later steps. The spec is [docs/macro-package.md](docs/macro-package.md); shared fixtures pin both validators' findings.

- Verification depth for projects: four new sections in `project.yaml` and four new steps of `chipleap verify PROJECT` ([docs/projects.md](docs/projects.md)). `formal` proves the design's own assertions and covers with SymbiYosys from `.sby` files ChipLeap writes (prove, bmc or cover; z3, yices, bitwuzla or abc pdr), and reports each failure with its property, file, line and step and the counterexample as values per step and a VCD. `cdc` checks clock and reset domain crossings on a Yosys netlist: synchronizers, handshakes, gray-coded pointers and FIFO memories are accepted; a missing synchronizer, logic before one, a multi-bit crossing that is not gray coded and a reset domain crossing are errors with their path; asynchronous inputs, inputs of another clock, synchronized resets and waivers with a reason are declared in the project. `equiv` proves the RTL equal to ChipLeap's synthesized netlist and LibreLane's synthesized netlist equal to its routed one, with Yosys's equivalence passes (or EQY), and checks what induction leaves from reset, so a difference comes back as a counterexample. `gls` runs the cocotb tests on the routed netlist with the SDF of the same run on Icarus 13 (or on the synthesized netlist with zero delay). The default steps are now `lint,sim,coverage,formal,cdc,synth,equiv`; `gls` runs with `pnr` when named or with `all`.
- Coverage closure: the coverage step says how many points the latest tests newly reached, and the MCP tool `coverage_gaps` returns the points never reached with their source lines and the project's test functions.
- MCP tools `prove_rtl`, `check_assertions` (an assistant's proposed assertions proved in a copy of the module, never in the project; expressions limited to identifiers, numbers, operators and a few system functions), `equivalence_rtl`, `cdc_rtl` and `gate_sim_rtl`, which run logs record and `chipleap replay` re-runs, and the prompts `propose_assertions` and `close_coverage`.
- `scripts/install_formal_tools.sh` builds SymbiYosys and EQY from the YosysHQ tag that matches the installed Yosys, with z3 4.15 beside them (`CHIPLEAP_SBY`, `CHIPLEAP_EQY`); `scripts/install_iverilog13.sh` installs Icarus 13 beside the system one for IHP gate-level simulation (`CHIPLEAP_IVERILOG`). `chipleap doctor` lists SymbiYosys, EQY and z3. Solvers are capped at 8 GB each (`CHIPLEAP_SOLVER_MEMORY_MB`).
- Every simulation gets the project's parameters as JSON in `CHIPLEAP_PARAMETERS`, so a test can read them on a netlist, which has none left. The UART example proves its transmitter's line in each state, declares its asynchronous receive line, and passes its tests on its routed netlist with SDF delays.
- Chips: a project's `chip` section ([docs/chips.md](docs/chips.md)) turns its RTL, any number of `macro/v1` packages and a pad ring of IHP SG13G2's `sg13g2_io` cells into one chip GDS. Pads name bits of the core's ports (input or output pads by the port's direction), analog nets or supplies; macros name their package, place and pin connections. `chipleap verify PROJECT --steps chip` builds it in LibreLane's Classic flow with the ring's cells as placed instances, routing kept off the ring, a power grid joined to the IO ring's own rails and macro supply pins strapped to the standard-cell rails; adds IHP's bond pads, seal ring and fill; and checks it with IHP's LVS deck on the chip without its IO cells (standard cells and macros compared at transistor level), IHP's DRC deck on the whole die (density included, recommended rules not), the supply hookup from the DEF and a GDS precheck (top cell, layer map, cell names, zero-area shapes, PR boundary, outline and grid). It writes a bond map in CSV and JSON. `chipleap chip plan` and the MCP tool `plan_chip` show the floorplan without running a tool; `assemble_chip` builds the chip. `chipleap.macro.layer` is the macro layer the chip uses, for `macro/v1` packages and for the PDK's own macros (an SRAM of `sg13g2_sram`): views, pins, reserved names and LibreLane's `MACROS`. The UART example is a chip with aispice's StrongARM comparator on its receive line: 33 pads, 1.52 mm with the seal ring, DRC and LVS clean.

- SRAM macros in the layout (D3 part a). The accelerator's activation and weight buffers become IHP's own `sg13g2_sram` macros when the build can take them without a change to its schedule (GEMV, one DMA read port, COLS of 4, 8 or 16): the RTL's `SRAM_BUF` reads each chunk's bank word a cycle before the chunk issues, from an address kept in registers a cycle ahead, and the issue registers the word in the operand registers as it does the flop array's, so the RTL tests match the flop buffers and the model cycle for cycle, stalls included. `verify --steps pnr` then routes the accelerator with the macros at the design's buffer sizes, in rows above and below the logic, each under a macro power grid (`chipleap.macro.grid`), timed at every corner from their liberty and checked by LVS as boxes, and compares cells plus macros with the model's estimate; other builds keep 16-word flop buffers and the result says why. `chipleap.macro.sram` lists the PDK's single-port macros and builds banks from them; `chipleap.gen.banks` writes the macro-backed top.
- A project's `macros` section lists the hard macros its RTL instantiates: IHP SRAMs (`cell`) and `macro/v1` packages (`package`), named as a chip's macros are and held to the same name rules. Lint and synthesis read black-box modules written from the SRAMs' names and the packages' manifests, simulation uses the PDK's models and the packages' Verilog, and place and route sizes the die, places the macros (or puts them where `at_um` says in a die of `pnr.die_um`), draws the SRAMs' macro grid and straps the packages' supply pins to the rails. Before LibreLane runs, no macro may also be a module of the RTL, and after it the merged GDS cells and subcircuits are checked: the chip's checks (`chipleap.chip.merge`), with the project's top in the chip top's place. Steps that do not model a macro yet skip and say so. `examples/sram` is a scratchpad in one macro.
- The chip's power grid (D4) takes pdngen's macro grid for a PDK macro whose supply stripes run across it, instead of refusing it.
- The steps after synthesis run on a project with hard macros, each with the macro as a box with its ports: formal makes it a cut point, CDC a state element of the clock its port samples on, equivalence turns its pins into compared outputs and shared inputs (with the box kept on both sides, Yosys proved a netlist that writes the SRAM when it should read equal to the RTL), gate-level simulation runs the PDK's timing model under the SDF, scan insertion and ATPG leave it off the chains and out of the test (inputs not observed, outputs held at 0), power and IR drop read its liberty and LEF, UPF places it inside its domain, and an ECO passes its views on but never the power grid script. A chip places its core's macros inside the pad ring, and its LVS compares IHP's SRAMs as boxes with their pins checked (IHP's deck does not match IHP's own SRAM at transistor level, on its own either); off-grid pin markers inside the PDK's own macros are reported apart in DRC. The commercial tools still skip such a project.
- A chip's check that no macro is named like a module of its core reads every module the core's sources define, black boxes and modules the core's top does not instantiate included. It listed the modules after Yosys's `hierarchy`, which drops both, and LibreLane reads the core's sources whole beside the macros' black boxes, where a module of the RTL replaces a black box of the same name.

- The whole SoC placed and routed (D3 part a): `chipleap verify DIR --steps soc` lays out X-HEEP with the accelerator as one block on IHP SG13G2 in LibreLane, with every memory in IHP's SRAM macros, at the design's clock or `--soc-clock MHZ`. X-HEEP at the pinned commit is copied into the step's directory and rendered there for the configuration ChipLeap writes from `design.yaml`; X-HEEP's own FuseSoC lists its sources and runs its generators (`scripts/install_fusesoc.sh`, `CHIPLEAP_FUSESOC`; a RISC-V GCC compiles the boot ROM); ChipLeap writes the top (`chipleap_soc`: the accelerator on X-HEEP's external crossbar, peripheral bus and interrupt; the pads' signals of the peripherals the configuration has, the pad control bus and, with external memory, the CPU's data port and the DMA's read and write ports to the external slave window brought out; the other external slave ports and the absent peripherals' pins tied off), X-HEEP's `sram_wrapper` in macros with a bit mask, the clock gates on IHP's integrated clock gate (a gate X-HEEP marks not functional passes the clock through) and the constraints (JTAG and the SPI slave as asynchronous clocks, the I2S's source-synchronous outputs held to the cycle) (`chipleap.gen.soc`). Slang reads the SystemVerilog; synthesis runs first, ChipLeap checks its netlist with Yosys's `check` and sizes the floorplan for its cells, and the same run goes on to the layout, with pins on the west and east edges between the macro rows. The step reports setup and hold at every corner, the clock met or missed beside the model's limit for the SoC, the macros against the model's banks and buffers, the model's logic against LibreLane's synthesis, and the run time; LibreLane gets 24 hours unless `CHIPLEAP_PNR_TIMEOUT` says otherwise. `chipleap doctor` lists FuseSoC.

### Changed

- The model prices X-HEEP's banks on IHP SG13G2 with the PDK's macros that hold them (32-bit words with a bit mask, as the SoC's layout builds them): a 32 KiB bank is eight 1024 x 32 macros, 1.121 mm2, where the density formula gave 0.947 mm2. The SmolLM2 example keeps its design; its area is 3.68 mm2 (was 3.50).
- The place and route step fails on a slew or capacitance violation at any corner, and reports both counts.
- ChipLeap's X-HEEP configuration leaves out the SPI host, the I2C, SPI2 and the I2S, which nothing in the model uses and which were most of X-HEEP's logic (each SPI host about 62 kGE on IHP SG13G2), and gives the DMA one master port, as the model's DMA moves 4 bytes per cycle, and two channels. On the SmolLM2 example the SoC's standard cells go from 3.233 to 1.842 mm2 in LibreLane's synthesis and the block from 1,278 to 582 pins.
- The model runs an X-HEEP SoC on IHP SG13G2 at the design's clock or what the SoC meets, whichever is lower, since the CPU reads its SRAM in one cycle: the bank macro's clock to output (7.39 ns for the 1024 x 32 at the slow corner) and the crossbar, the CPU's load path and the wire after it ([docs/model.md](docs/model.md#the-socs-clock)). The CPU, its bus and the accelerator share that clock; the model warns when the limit sets it, and the reports give the SoC's clock, what the SoC meets and what the accelerator meets on its own. The SmolLM2 example's design runs at 56.7 MHz instead of 90 and makes 1.78 tokens per second instead of 2.22, and exploring its spec recommends a larger design.
- The GEMV adder tree takes its operand widths from a function of the loop variable instead of `$clog2` of it, which Yosys's slang frontend cannot evaluate. The netlist is the same.
- The accelerator's area model is fitted again, to 24 synthesized configurations instead of 12 (one to eight ports, 4 to 64 MACs): 24.9 kGE of control, 2.8 kGE per read port, and per dataflow a cost per MAC and per lane, column or edge, within 2.8 % on average and 7.1 % at worst of each configuration left out. Twelve were too few for eight terms: when the core went inside its `chipleap_accel` wrapper, Yosys's result moved by 3 to 5 % on some designs with the logic unchanged, the error went to 5.0 % and 9.8 %, and a term turned negative. The synthesized-delay bounds follow the same runs: 4.35 ns for GEMV, 3.77 ns weight-stationary, 3.53 ns output-stationary. On IHP SG13G2 a GEMV engine whose buffers are banks of macros now also has the banks' interface priced (`accel_bank_kge`): the macros' write path and the registers that read each chunk a cycle ahead, 5.5 kGE plus 0.10 kGE per MAC, plus 1.0 kGE with a double buffer, fitted to 12 macro-backed builds within 0.67 kGE. The SmolLM2 accelerator's logic is now 0.332 mm2 in the model against 0.331 mm2 in ChipLeap's synthesis of its macro-backed core (+0.4 %), where it was 0.272 mm2. `chipleap.verify.synth.synthesize_banked` synthesizes such a core on its own.
- The LibreLane signoff settings live in one function, `chipleap.verify.pnr.signoff`, that the accelerator's and a project's place and route share.
- The project sections `dft`, `power`, `ir_drop`, `upf`, `eco` and `macros` are read.
- `chipleap_accel` keeps its ports and parameters and wraps `chipleap_accel_core`, which holds the logic and takes `SRAM_BUF`.
- `examples/uart` has a `dft`, a `power` and a `upf` section, so `--steps all` routes its scan netlist.
- Timing: the accelerator's DMA serves its read ports in parallel. It used to hand the words of a transfer to the ports one after another within a cycle, so each port's word waited on the ports before it: a chain of 32-bit compares and adds that grew with the number of ports and set the clock of every design with four. Now port `p` reads words `p`, `p + ports`, `p + 2 ports` and so on, with an address generator of its own. After routing with LibreLane the GEMV 2 x 8 engine with four ports meets 100 MHz at the slow corner (1.08 V, 125 C) with 0.37 ns to spare, about 104 MHz, where it met about 71 MHz; its worst paths are now the weight unpacking and the dot product, as with one port. Cycle counts without stalls are unchanged and the cycle model stays exact. Under random stalls a transfer waits for its slowest port, and the model adds that port's expected lateness. A read port costs 2.5 kGE, and the area and synthesized-delay fits are repeated on the new RTL.
- The GEMV adder tree gives each adder operands cut to the width its sum needs, so synthesis builds one carry-save sum per lane whatever order Yosys visits the design in. Left to Yosys, a change elsewhere in the RTL could leave one adder full width and split the tree into three carry-propagate adders in series.
- The model's clock cap on IHP SG13G2 is refitted to designs routed with LibreLane on the new RTL, at the slow corner: 9.33 ns for the single-port designs, 0.47 ns more per doubling of a GEMV engine's lanes, and at least 8.81 + 0.296 ns per port, a line through the GEMV 1 x 8 engine with one port and with eight (about 110 and 89 MHz). Designs with up to four ports are allowed 100 MHz, except GEMV engines with four or more lanes or more than eight columns; with the old DMA four ports were capped at about 71 MHz and eight at about 46 MHz. The routed GEMV 4 x 8 engine with two ports meets about 97 MHz, a little under the 99 MHz it met before, on the same slot-select path. The GEMV 1 x 8 engine with sixteen ports meets about 89 MHz, above the 74 MHz the line allows; with the old DMA it met about 24 MHz.
- The model prices an accelerator's buffers on IHP SG13G2 with the PDK's single-port macros that hold them: a GEMV engine with COLS of 4, 8 or 16 gets the banks the layout places, any other build each buffer slot in macros of 32-bit words. A slot costs its whole macro, so the SmolLM2 example's 1 KiB slots of 64-bit words cost 256x64 macros, half empty: 0.373 mm2 for its buffers, the area of the routed macros, where the density formula gave 0.186 mm2. The place and route step checks the model part by part: macros against the layout's, the logic estimate against LibreLane's synthesis, and what place and route adds to that synthesis, reported apart (`model_buffer_um2`, `synth_cell_um2`, `model_cell_error`, `pnr_cell_growth`).
- Place and route gives an accelerator with more than eight read ports 35 % core utilisation instead of 45 %: with 16 ports the GEMV 1 x 8 engine failed global routing on congestion at 45 %, with its timing met. At 35 % global routing finishes with no overflow and the routed design is LVS and antenna clean, with one Metal2 shape a 5 nm grid square under the minimum area.
- Timing: the accelerator's core reads its tile descriptor from a register loaded a cycle ahead, instead of selecting the descriptor of its buffer slot after the registers. The select and the buffer tree of the slot's net led into the GEMV engine's operand registers and accumulators, and set the clock of the routed GEMV 4 x 8 engine with two ports and the 1 x 8 with eight and sixteen. After routing at the slow corner the 1 x 8 engine now meets about 99 MHz with eight ports (-0.09 ns) and 96 MHz with sixteen (-0.41 ns), where it met about 89 MHz with both. The 4 x 8 engine met about 103 MHz (+0.31 ns) in one run and 98 MHz (-0.23 ns) in another of the same logic, where it met about 97 MHz; its worst paths are now the dot product and the accumulator row select. Cycle counts are unchanged, stalls included. The register costs about 1.2 kGE. The model's clock cap follows: 0.46 ns per doubling of GEMV lanes and at least 8.966 + 0.1413 ns per port, so up to seven ports are allowed 100 MHz, eight about 99 MHz and sixteen about 89 MHz.

### Fixed

- Timing signoff now applies the PDK's 5 % derate (`TIME_DERATING_CONSTRAINT`: late paths 5 % slower, early ones 5 % faster) to RTL projects' place and route, ECOs and chips. ChipLeap's constraints computed it as `TIME_DERATING_CONSTRAINT / 100`, LibreLane 3.0.0.dev44 passes IHP's value as the integer 5, and Tcl's integer division made the derate 0. Every timing figure ChipLeap has published from LibreLane runs so far was computed without it: place and route, the chip step, the README, the site and the demos. The constraints now divide by 100.0, the chip's constraints carry the same derate, and the chip's own timing at its ports applies it as well. On `examples/uart` with LibreLane 3.0.0.dev44, the setup slack at the slow corner goes from 6.210 to 6.002 ns in place and route (about 264 MHz to about 250 MHz), and from +0.968 to +0.667 ns through the pads. The accelerator's place and route uses LibreLane's own constraints, which have the same integer division in 3.0.0.dev44 and divide by 100.0 from LibreLane 3.0.14 on.
- Place and route no longer fails signoff on a routed shape under the minimum metal area. OpenROAD's detailed router now and then left a short Metal2 stub between a Via1 and a Via2 under IHP's 0.144 um2 (rule M2.d): one shape in 4 of 12 accelerator runs, and LibreLane then stopped without its final views. LibreLane now runs up to detailed routing, ChipLeap measures every routed shape on Metal2 to Metal5 against the minimum and extends each one under it at an end with room, and the rest of the flow runs on the patched layout through `OpenROAD.DEFtoODB`. The same applies to RTL projects, chips and ECOs.
- Place and route of an accelerator or project with SRAM macros repairs after global routing and caps wire length at 300 um before and after it. The routed SmolLM2 accelerator had 38 slew and 21 capacitance violations at the slow corner, all on the macros' `A_DIN` pins, which the DMA's write word reaches over about 800 um; repair after global routing alone left 51 and 14, since LibreLane's derived maximum wire length (about 5 mm) never split a net. Now it has none, and meets 90 MHz at the slow corner with 0.69 ns to spare.
- Place and route: at `CHIPLEAP_PNR_TIMEOUT` (3 h by default), on Ctrl-C, SIGTERM or SIGHUP, and when the MCP server cancels a `verify_soc` call or shuts down, ChipLeap now stops LibreLane's container as well. It used to stop only the `docker` client, so the container went on routing to the end, and a cancelled MCP call or a server shutdown stopped nothing. The run's containers are recognised by a label of their own, and no other container is touched. A run that times out fails the step with the limit in its summary instead of ending `chipleap verify` with a traceback, and a second run in the same work directory fails at once instead of overwriting the first. LibreLane no longer inherits ChipLeap's standard input: a containerised run switched the terminal to raw mode through it, so Ctrl-C never reached ChipLeap, and under the MCP server it could read the client's requests.

### Security

- `chipleap macro check` read a package through symbolic links: a package whose files, `evidence/` or summaries were links into a sibling directory (another package's evidence, say) passed with files that are not in it, and an evidence input that linked out of the package was hashed, with the start of its SHA-256 in the report. The validator now reads only regular files inside the package, never through a link, and a FIFO no longer blocks it; anything else is `file.unreadable`.
- `chipleap macro check` passed views that the tools read differently: a LEF whose first definition of the macro was written in lower case (OpenROAD reads LEF keywords in any case and keeps the first macro of a name), a liberty file with a second cell of the macro's name (OpenSTA keeps the last), and a Verilog port declared on both sides of an `ifdef` (Yosys defines `SYNTHESIS` and reads one side). LEF keywords are now read in any case, a macro, cell or pin defined twice makes the LEF or liberty file unreadable (`lef.parse`, `lib.parse`), and a module or port declared more than once is the new rule `verilog.duplicate`. The spec and the shared fixtures carry all three.
- A project or a bundle from someone else's repository could make ChipLeap delete or overwrite files outside it: shipped with `build/` (or `build/pnr`, `build/pnr/src`, `build/<tool>`, a bundle's `verify/`) as a symlink to the home directory, a step emptied or wrote into the directory the symlink pointed at. ChipLeap now reaches its build, work and output directories one component at a time without following a symlink, and a symlink on the way stops the step with an error that names it. A symlink inside a step's work directory is removed before the step writes there, and nothing it points at is touched; reports, bundle files, `project.yaml` and the summaries `chipleap.macro.write_evidence` puts in a macro package's `evidence/` are written without following one; the directory given with `-o`, or verified as a bundle, may not be a symlink. A directory that `-o` creates holds a `.chipleap` file, and only a directory with one is ever emptied. On Windows a directory junction, or any other reparse point, is treated as a symlink: refused on the way, and removed inside a work directory without being entered, so what it leads to is never deleted. `chipleap.rtl.builddir` holds the checks.
- The steps after place and route reuse a result in `build/` (a scan insertion's netlists, the routed run, an ECO's run, the gate-level VCD) only when ChipLeap on this machine recorded it: a manifest of every file's SHA-256, authenticated with a per-user key, and the hash taken of the exact bytes a tool then gets. A routed run, a LibreLane configuration, a Tcl script or a netlist that a repository ships or that changed afterwards fails the step unopened, and an ECO passes on to LibreLane no variable that names a script, hook or plugin and no substitution. Each OpenROAD run gets a private directory with copies of its inputs and nothing else of the project, and netlists are read within limits (size, modules, instances, bus width, hierarchy depth with loop detection, scan-chain length).
- Gate-level simulation and equivalence read the routed run (the ECO's, when one of the current run exists) only as ChipLeap recorded it, hash checked; there is one routed run for every step. Gate-level simulation holds a scan netlist's scan inputs low.
- Tools are found only on absolute `PATH` entries, never in the project while a step runs, and every tool gets `PATH`, `PYTHONPATH` and `LD_LIBRARY_PATH` without empty, relative or project entries, so a repository's own `vvp`, `fault`, `docker` or `sitecustomize` is never run.
- The MCP tools after place and route say in their descriptions that they run the project's own code (its design, tests and constraints) and are for trusted projects only.
- `chipleap macro check` reads a package from someone else within limits that no real macro comes near ([docs/macro-package.md](docs/macro-package.md), "Limits"), the same as aispice's. A file over its size limit is not read; nesting in TOML, JSON and liberty, pins, tokens, GDS records, elements, cells and reference depth have caps; a GDS cell that contains itself is an error; an array reference is measured from its corner instances, so a 32767 x 32767 array costs no more than one instance; and a report lists at most 1,000 findings and counts the rest. Each case ends in a finding with the same rule id in both tools (`file.too_large`, `file.unreadable`, `gds.cycle`, `check.limit` and a `.limit` rule per file), never in a hang, a crash or a machine out of memory. Two readers that took quadratic time (a Verilog range search, SPICE continuation lines) are linear.
- A macro package placed in a chip is treated as untrusted: it is copied through the project's confined read, checked against `macro/v1` before use, and only the files its manifest names are read. ChipLeap writes the views the flow uses itself (a LEF of the statements it understands, the GDS moved to the LEF's origin, a liberty from the manifest, the SPICE subcircuits with device lines only), and a package cannot replace a cell of the chip in the layout or the LVS netlist: its name is lowercase and outside every name of the PDK's libraries and the flow, its GDS cells (read as raw bytes, each defined once, every reference inside the file) and subcircuits (case folded, as SPICE does) stay in its own name space, and two packages' name spaces may not overlap. Those checks come early; the guarantee is at the merges: the chip top's Verilog modules must be distinct, and the GDS cells and subcircuits LibreLane actually merged (read from its resolved configuration, with the chip top and the routed design's vias counted too) may have no name defined twice, unless by the same PDK file or identically. IHP's DRC and LVS runners, which build shell command lines from their arguments, run in a private directory on copies of their inputs.
- A project could have its own programs run in place of the tools. An empty entry, `.` or any other relative entry in `PATH` names the current directory, which during a run is the project or its build directory, so an executable named `z3`, `yosys` or `sby` that a repository shipped ran instead of the real tool, started by ChipLeap or by a tool that starts another by name. Tools are now looked up only in absolute `PATH` directories, never in one that leads into the project or an allowed directory while a step runs, and every program ChipLeap starts gets a `PATH` made of those alone; version probes run in an empty directory, so a project's `cocotb` package cannot be imported by one; relative tool variables, `CHIPLEAP_LIBERTY` and `PDK_ROOT` are not used, and the step or `chipleap doctor` says why. The verification steps also never delete, write or read through a symlinked `build/`, `build/<step>` or `build/pnr`, and their tools run under Landlock like lint and synthesis.

## [0.3.0] - 2026-10-11

### Changed

- Timing: the accelerator meets 100 MHz on IHP SG13G2 at the slow corner (1.08 V, 125 C) after routing with LibreLane, not only at the typical one: about 109 MHz for the GEMV 1 x 8 engine, 105 and 107 MHz for the 4 x 4 weight- and output-stationary arrays. The GEMV engine registers its operands before the multipliers, the weight- and output-stationary arrays register their edge feeds, the loader decides where the next tile goes a few cycles before it needs to, each DMA read spends its first cycle setting up its address and counts, the weight-stationary array reads an accumulator one cycle before it writes it back, and the loader decides whether another tile follows from the extent still to cover, with one compare. Each stage adds at most one cycle per tile or transfer, and the cycle model follows exactly.
- The model caps the accelerator's clock on IHP SG13G2 at what it closes timing at after routing, at the slow corner: the period of the routed single-port designs, longer for a wider GEMV datapath, and a period that grows by 1.95 ns per port, fitted to routed GEMV engines with two and four ports (about 99 and 71 MHz). Designs above it are infeasible, and the explorer lowers the clock when a change of accelerator needs it. Clock steps now include 75 and 90 MHz.
- Place and route: `verify --steps pnr` signs off setup at the slow corner. LibreLane's repairs aim for 0.8 ns of slack after placement and 1.6 ns after global routing, because detailed routing took up to 1.6 ns away and nothing repairs timing after it.
- Synthesis sizes gates for a 5 ns target (the 100 MHz the node allows, signed off at the slow corner) instead of the shortest path ABC can reach, which had inflated short-path designs by up to a fifth. The accelerator area model is refitted to it over 12 configurations: 2.9 % leave-one-out error on average, 8.4 % at worst.
- ChipLeap is on PyPI: `pip install chipleap`.

## [0.2.0] - 2026-10-10

### Added

- Place and route: `chipleap verify --steps pnr` (or `--steps all`) runs the accelerator through LibreLane on IHP SG13G2, with timing at every corner, KLayout DRC with IHP's rule deck, LVS and antenna repair, and keeps the GDS. The open-PDK example's 1 x 8 GEMV engine routes to a 0.81 mm2 core with clean DRC and LVS, about 120 MHz at the typical corner and 77 MHz at the slow corner. `scripts/render_gds.py` draws a GDS in the PDK's colours.
- A `standalone` platform: the accelerator as AXI4 IP for any host (an Arm, RISC-V or FPGA SoC), with an AXI4-Lite register port, AXI4 read and write masters, a plain C driver and a protocol-checking AXI testbench. Set `platform: standalone` in a spec or pass `--platform standalone`; reports give the IP's area apart from the assumed host system.
- Commercial EDA tools next to the open ones: simulation with Cadence Xcelium, Synopsys VCS or Siemens Questa through one simulator-neutral SystemVerilog testbench driven by the generated C driver, and synthesis with Cadence Genus or Synopsys Design Compiler, with Innovus scripts for the netlist (`--sim-tool`, `--synth-tool`). Runs on this machine or on a design server over ssh (`--remote`, `--remote-setup`); the MCP server cannot choose a host or a setup command.
- `chipleap tech add`, `list` and `remove`: measure a PDK of your own from its liberty files into your config directory, never into a repository, and use it like the built-in technologies.
- README images: the die render, an animation of the agent's decisions with every floorplan to scale, the report, and the routed layout (`scripts/make_readme_visuals.py`).

### Fixed

- Synthesis failed for bundles given by a relative path.
- The hero callouts drifted off their blocks on phones while scrolling, and figures on phones used a display face whose 1 read oddly.
- `chipleap require` now sizes external memory per process node at the rate that node's I/O allows, as the evaluator does. It no longer rules out serial memories that run below their rated speed on the IHP 130 nm pads, such as two octal PSRAM channels for SmolLM2 135M at 2 tokens per second; `required_resources` reports `channels_by_node`.
