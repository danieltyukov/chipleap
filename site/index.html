Design the chip your model needs.

ChipLeap explores the architecture before anyone writes RTL: memory system, external memory, dataflow, compute and process node, each choice explained. Then it generates a RISC-V SoC on X-HEEP and checks it with open tools.

Watch it design a chip

Llama 3.2 1B decoding at 5 tokens per second, within 8 mm² and 400 mW. The agent starts from a bare microcontroller, names what limits it, tries every single change, keeps the best and says why. The floorplan is drawn to scale at every step. This run evaluated 2,153 designs in under 5 seconds.

  1. Start

    Start from a bare microcontroller

    A CV32E20 at 100 MHz with two 32 KiB banks on IHP 130 nm. The CPU does every multiply itself, and the 642 MiB of weights and KV cache do not fit in a 64 MiB HyperRAM.

    0.0097 tokens per second

  2. Decision 1

    Move to 65 nm, 200 MHz and LPDDR2

    A newer node allows faster clocks and memory interfaces at lower energy. Before this step 100% of the time went to compute.

    0.0097 to 0.019 tokens per second, 854 to 327 mJ per token, 3.53 to 2.92 mm², now buildable

  3. Decision 2

    Add a GEMV engine

    Matrix multiplies dominate and the CPU does them one MAC at a time. Before this step 100% of the time went to compute.

    0.019 to 1.71 tokens per second, 327 to 86.2 mJ per token, 2.92 to 3.49 mm²

  4. Decision 3

    Move to 28 nm, 400 MHz and LPDDR4X

    A newer node allows faster clocks and memory interfaces at lower energy. Before this step 75% of the time went to the accelerator's ports.

    1.71 to 3.31 tokens per second, 86.2 to 29 mJ per token, 3.49 to 2.43 mm²

  5. Decision 4

    Move to 16 nm, 800 MHz

    A newer node allows faster clocks and memory interfaces at lower energy. Before this step 76% of the time went to the accelerator's ports.

    3.31 to 6.19 tokens per second, 29 to 27.9 mJ per token, 2.43 to 1.34 mm², meets every target

  6. Decision 5

    Switch to LPDDR5

    A slower interface can be cheaper in area and energy per bit. Before this step 78% of the time went to the accelerator's ports.

    throughput unchanged at 6.19 tokens per second, 27.9 to 22.5 mJ per token, 1.34 to 1.00 mm²

  7. Decision 6

    Make the banks 16 KiB

    Unused SRAM costs area and leakage. Before this step 78% of the time went to the accelerator's ports.

    throughput unchanged at 6.19 tokens per second, 1.00 to 0.97 mm²

    No single change lowers the energy further, so the agent stops with a 4 x 8 GEMV engine next to a CV32E20 at 800 MHz in 16 nm, fed by LPDDR5: 6.19 tokens per second at 22.5 mJ per token in 0.97 mm². Its weights now arrive as fast as the accelerator's ports take them in, so more ports would raise the token rate but not lower the energy per token.

One loop, from requirement to RTL

Each stage writes a file the next one reads, so every result can be opened, edited and checked.

  1. DescribeA YAML spec: the model, context and precision; tokens per second, area and power; the nodes and memories you can use.
  2. Sizechipleap require turns the target into bandwidth, MAC rate and capacity, and rules out what cannot deliver.
  3. ExploreThe explainable agent plus a seeded global search: a decision log, a Pareto front, a recommended design.
  4. GenerateAn X-HEEP configuration, the accelerator in SystemVerilog, a register map, a C driver, a testbench, a datasheet.
  5. VerifySimulation against a golden model, cycles against the model, synthesis on IHP SG13G2, X-HEEP's own checks.

Ask in plain words. Get a chip.

ChipLeap is an MCP server. Its tools answer architecture questions rather than run single EDA tools, so Claude, Cursor, VS Code or Codex can take a requirement, write the spec, explore, question the bottleneck, then generate and verify the SoC. Every call can be logged and replayed.

claude mcp add chipleap -s user -- chipleap mcp

Design the smallest chip on the open IHP PDK that runs SmolLM2 135M at two tokens per second.

required_resources(spec)

77 MB read per token: 155 MB/s sustained and 74 MiB resident. At 130 nm only serial memories work: HyperRAM or octal PSRAM, several channels for capacity.

explore_designs(spec, objective="area")

1,758 designs evaluated. The agent added a GEMV engine, doubled the memory channels, moved the weights to octal PSRAM, then made 7 trims to the SRAM, buffers and array, and stopped at the smallest design that still meets the target.

Recommended: CV32E20 at 100 MHz, 32 KiB of SRAM, a 1 x 8 GEMV engine and 2 octal PSRAM channels. 2.29 tokens per second, 44 mW, 3.4 mm², limited by external memory. Shall I generate and verify it?

Yes.

The arithmetic that sets the limit

At batch one, decode reads every weight once per token, so the external memory sets a ceiling no amount of compute can raise. Pick a model and a memory.

Where it fits

Agentic EDA suites from Cadence, Synopsys and Siemens, and startups such as ChipAgents, Chipmind and SigmanticAI, mostly start from a specification or RTL on licensed tools. Workload-to-chip companies such as Architect Labs and Cognichip are closed services. Academic tools such as Timeloop, ZigZag and LLMCompass model accelerators without generating hardware. ChipLeap works on the step before the specification, and hands one over.

Run it on your machine

Python 3.10 or newer. Verilator, Yosys, sv2v and the IHP PDK are optional: chipleap verify uses what it finds, and chipleap doctor lists it.

View on GitHub Read the docs 
# install
uv tool install git+https://github.com/danieltyukov/chipleap

# write a spec, size it, explore
chipleap init llama.yaml
chipleap require llama.yaml
chipleap explore llama.yaml -o out

# simulate, synthesize, run X-HEEP checks
chipleap verify out

Questions

Does it need a commercial EDA licence?

No. Simulation and lint use Verilator, synthesis uses Yosys with sv2v, the technology data comes from the IHP SG13G2 open PDK, and X-HEEP's own generator checks the configuration. The model, the explorer and the generators need none of them.

How accurate is the model?

For the accelerator, the model predicts the generated RTL's cycle count exactly in simulation without memory stalls, and within a few percent with random stalls. Its logic area is within 4% on average of Yosys synthesis on IHP SG13G2, and the synthesized logic runs faster than the clock the model allows there. Memories, CPU and energy rest on technology data that is measured for IHP SG13G2 and scaled from published figures for the other nodes, and reports say which is which. docs/model.md lists every number and its source.

Why X-HEEP?

It is an open, configurable RISC-V microcontroller from EPFL with a Python configuration API, an accelerator interface and several chips taped out. Its generator validates what ChipLeap writes.

Can I use my own model or network?

Yes. Any decoder-only transformer can be described by its shape, and other networks as convolutions, depthwise convolutions, matrix multiplies and element-wise operators.

What does the generated accelerator not do yet?

It computes int8 activations against int8, int4 or int2 weights with int32 results. Requantization, activation functions and int4 group scales run on the CPU, and the model counts them there. It has not been taped out.

Is it affiliated with EPFL, IHP or any company named here?

No. ChipLeap is an independent open-source project.
